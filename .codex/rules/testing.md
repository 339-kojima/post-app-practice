# テストのルール

## 使用するテスト

- Laravel のテストランナーを通じて PHPUnit を使用する。
- HTTP 経由で確認するユーザー向けの動作や認可にはフィーチャーテストを追加する。独立して検証できるロジックにはユニットテストを追加する。
- テストファイルは `tests/Feature/` または `tests/Unit/` に置き、ファイル名は `*Test.php` とする。
- テストメソッド名は検証内容が分かるものにする。既存の `test_...` 形式に合わせる。

## テストの組み立て

- 機能変更では、その動作と関連する受け入れ条件を確認するテストを追加または更新する。
- フィーチャーテストでは `Tests\\TestCase` を使い、認証が必要な場合は `actingAs()` でユーザーを設定する。
- DB を使うテストでは `RefreshDatabase` を使い、ファクトリーやモデル作成で必要なユーザー・投稿・カテゴリなどを準備する。
- 成功時のリダイレクトや表示だけでなく、必要に応じてバリデーションエラー、セッションの入力値、認可結果、データベースの作成・削除も検証する。
- テストデータは対象の動作が読み取れる内容にし、順序や関連付けを確認する場合は必要な日時・別レコードを明示的に用意する。

## テストの実行方法

- テスト一式はリポジトリのルートから `./vendor/bin/sail test` で実行する。
- 1 クラスだけ実行する場合は `./vendor/bin/sail test tests/Feature/ExampleTest.php` のように、対象のテストファイルを指定する。

## 失敗時の対応と報告

- テストが失敗した場合は原因を調べて修正し、再実行する。
- 最終報告には実行したコマンドと結果を記載する。
- PR 本文には関連する受け入れ条件ごとに、実施したテストコマンドと成功・失敗の結果を記載する。
